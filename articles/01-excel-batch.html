不写代码批量处理 100 个 Excel 文件：配一次，之后拖进文件夹就跑

行政、财务、运营手里常有一堆结构相同、每周都要重做一遍的表。典型动作是：打开表 → 按「金额 > 100 且状态 = 完成」筛一遍 → 按部门汇总 → 另存为新表 → 下一个文件。10 个文件还能忍，100 个就是一整天，而且第 37 个很容易手滑把原表覆盖了。

这类工作有两个特点：规则固定、输入是一批结构相同的文件。它不需要聊天机器人，需要的是把规则固化下来，并且不破坏原文件。

做法一：一条流程处理一张表（4 个节点）

在画布上依次放 4 个表格节点（v2027.1.0 新增），不用写 Python：

  1. 读表格：选 CSV / Excel，编码自动探测（UTF-8、GBK、BOM），列名列成下拉，不用记列号。
  2. 筛选：条件写 金额 > 100、状态 = 完成，多条件按 AND 组合。数字按数值比较（100 与 100.0 判等）。条件解析不出来会直接报错并列出当前列名，不会悄悄"不过滤"让你以为筛过了。
  3. 聚合：按「部门」分组统计金额合计。
  4. 写表格：填输出路径。默认输出新文件，目标已存在自动加 (1) 序号，绝不覆盖原表；要覆盖必须显式勾选。

节点之间传的是结构化的 rows / columns，不是把表格拼成文本——列名里带逗号也不会变成解析 bug。按 F5 跑一次，结果页能看每一步耗时与输出，也能导出。

做法二：一批文件用「批量运行」

把多个文件当成数据集：选 CSV/XLSX → 列映射 → 逐行执行 → 结果表。结果表把成功行、失败行、失败原因分列，可以点「只重跑失败行」，不必把 100 个文件重来一遍；中途断了还能断点续跑，不重复外发、不重复扣费。批次结果自动归档（默认 90 天 / 200 条），三天后仍能在「执行记录 → 批次」里找回并导出。

做法三：连「点运行」都省掉

「批量运行 → 文件夹监听」新建规则：选文件夹、绑定流程、设文件稳定时长（等文件写完再处理，避免喂进半截文件），然后显式启用。之后丢文件进去就自动跑；成功的移到 done/，失败的留原地，改动后自动重试。规则默认关闭、需二次确认，不会在后台偷偷扫描磁盘。

注意：文件夹监听走正式执行链路，会写执行记录并计入预算；它和不落库的「试跑」不是一回事。

免费版能跑到哪一步

上面 4 个表格节点、批量运行、文件夹监听都在免费版内。免费版限制的是数量：单流程最多 10 个节点、1 个 AI 接口、1 个定时任务、1 个 API 触发流程、1 个 MCP Server、1 个 A2A 智能体。这条 4 节点流程完全够用。
