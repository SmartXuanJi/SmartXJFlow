客户资料不想上传云端：本地跑 AI 的三种做法与边界

客户名单、合同、报价单想让 AI 帮忙整理，又不敢粘到网页对话框里。这不是多疑——多数云端工具会把输入送到服务商。真正可行的做法只有三种，边界差别很大。

做法一：完全不联网（很多人其实不需要模型）

先把需求拆开：筛选、汇总、格式转换、批量重命名、按列改写，这些都不需要模型。

这类工作用本地文件与表格节点就能做完：读表格 → 按条件筛行 → 分组统计 → 写回新文件。全程不发起任何网络请求，断网也能跑。很多所谓「要 AI」的需求，做到这一步就够了。

工具侧要能证明"真的没联网"：离线模式提供在线 / 离线 / 部分可用三态，离线时只保留白名单能力（编辑、模板、导出、本地文件、设置、历史），不会静默尝试连接云端。

做法二：本地模型（数据不出本机，但有代价）

GGUF、ONNX、语音识别、语音合成、图像/视频模型都能在本机推理。代价要提前说清：

  • 体积：模型按 GB 计，下载与磁盘占用都不小；
  • 硬件：先看本机 CPU / 内存 / 独显建议再挑模型，别下完 7 GB 才发现跑不动；
  • 首次配置：运行时依赖按需下载到应用目录，不污染系统 Python；缺 ffmpeg 时语音场景会提示，装到应用自己的目录，不改系统环境变量；
  • 能力边界：本地模型在长文本理解、复杂推理上仍弱于云端大模型，适合分类、抽取、改写、摘要这类任务。

做法三：云端模型 + 边界控制（BYOK）

继续用云端模型，但把"什么能出去"控制住：

  • 自配 Key：模型密钥由你自己填，费用直接与服务商结算，工具不代收、不托管；
  • 运行前提示：检测到疑似手机号、身份证、密钥等敏感内容时先提示，而不是直接发出去；
  • 导出脱敏：分享包、审计证据包、诊断包、配置备份会递归脱敏 api_key / token / password 这类键名与值；
  • 审计默认脱敏：证据包默认不含提示词与输出原文，「包含原文」需要显式勾选并留痕；
  • 只读分享链接：页面只给节点结构，不含提示词、SQL、密钥与输入默认值。

三个常被忽略的边界

  1. "离线模式"不是"全部功能离线可用"：它只保留白名单能力，云端模型、在线下载自然不可用。
  2. 接了外部工具就会外发：一旦配置 MCP / A2A 出口或 IM Webhook，数据会发到你配置的那个目标——这与"模型是否本地"是两回事。
  3. 本地加密不等于防物理接触：主密码体系能防止旁人直接读配置，但拿到整机与密码的人仍可解密；真正的合规要靠权限与流程。
