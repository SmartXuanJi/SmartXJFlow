会议纪要转待办：从粘贴文本到结构化输出

纪要里最有用的三行是「谁、做什么、什么时候」，但每次都要人从一大段话里抠出来。让模型做这件事不难，难的是格式每次一样、能直接贴进任务表。

三步搭完

  1. 输入节点：声明一个 text 变量，把纪要粘进去（也可以声明 file 类型，直接传 docx/txt）；
  2. LLM 节点：提示词里固定输出列——事项 / 负责人 / 截止时间 / 备注，并勾选 JSON 输出，避免模型自由发挥成散文；
  3. 生成文件：把结构化结果渲染成 Markdown（贴群里）或 Excel（进任务表）。

节点之间是变量传递，所以第 2 步的 JSON 字段名就是第 3 步的模板变量，改名要一起改——这也是"变量契约"存在的意义：改错会立刻在体检里报出来，而不是运行时才发现。

提示词怎么写更稳

你是会议纪要整理助手。只输出 JSON，不要解释。
字段：items[]，每项含 task / owner / due / note。
规则：
1) owner 未提及时填「未指定」，不要猜；
2) due 只接受 YYYY-MM-DD 或「未指定」，不要编造日期；
3) note 只写原文里出现过的信息；
4) 没有可执行事项时返回 {"items": []}。

三条规则对应三个常见问题：猜人、编日期、脑补细节。宁可留空，也别编。

让它可维护

  • 提示词版本历史：改坏了能回滚，改动可读差异；
  • 结果摘要带来源：摘要里的结论强制标注来自哪段输入，方便回查；
  • 样例数据试跑：先用两段脱敏纪要跑通，再换成真实内容；
  • 失败可重试：LLM 节点超时或返回非法 JSON 时，重试与降级策略要显式配置，不要静默吞掉。

边界

  • 模型会漏项。重要的是结果可核对：把原文与输出并排看，或加一条"输出条目数少于 X 时提示人工复核"的规则；
  • 数据去向取决于你选的接口：用云端模型就意味着纪要会发到服务商；敏感会议要么用本地模型，要么先脱敏（人名、金额、客户名替换）；
  • 免费版可配 1 个 AI 接口、单流程 ≤10 节点，这条 3 节点流程完全够用；本地模型属专业版。

可以顺手加的复用

把这个流程存成模板，下次换一份纪要直接跑；或者做成批量运行，一次导入多份纪要、逐份输出待办，结果表按"文件 / 事项数 / 失败原因"分列，失败的那份单独重跑。
