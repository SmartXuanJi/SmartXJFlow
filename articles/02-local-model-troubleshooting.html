本地模型下载完却跑不起来：依赖缺失与文件不完整的排查顺序

想在自己电脑上跑 GGUF / ONNX / 语音模型，试跑却只给一句英文报错——这类问题我见得最多的结论是：绝大多数「装了包还报错」不是缺依赖，而是模型文件没下完整、运行环境缺配套包或版本元数据、或缺 ffmpeg。按下面顺序查，别一上来就重装软件。

第 1 步：这台机器到底该跑多大的模型

「本地模型」页顶部显示本机 CPU / 内存 / 独显，并给出档位建议（适配本机 / 内存可能不足 / 需要独显）。先挑模型再看跑不跑得动，是最容易踩坑的顺序：有人下完 7 GB 才发现内存不够。判不出内存时它会建议「从 7B 试起」，不劝人上大模型。

在线下载支持断点续传，并会自动补齐所选规格对应的 ONNX 外部数据文件（*.onnx_data / *.onnx.data）；下完点「批量重新检测」重新识别后端与调用参数。

第 2 步：文件是不是完整的（最常见）

下载被中断时，文件可能是 0 字节、被截断，或只下到了 Git LFS 指针文本。onnxruntime 此时只抛一句 No graph was found in the protobuf，看起来像「缺依赖」，实际是文件里根本没有计算图。

处理：重新下载该模型；扫描阶段也会把不完整模型标成不可用并写明「请重新下载」，不用等试听失败才发现。如果重新下载后仍一样，考虑是不是把别的架构权重放进了该目录，换一个模型验证。

第 3 步：是「缺包」，还是「缺包的元数据」

运行时依赖按需下载到应用 extensions/，不污染系统 Python。为了不把 numpy / torch 这类基础库重复复制进来，安装走的是「只装主包 + 按需补配套依赖」，于是有两类不同报错：

  • No module named 'diskcache'：确实缺配套包 → 在失败提示点「自动安装」，按主依赖一次性补齐，装完自动重试；已能导入的包不重复下载。
  • The 'requests' distribution was not found / No package metadata was found for ...：模块在，但发行包元数据（dist-info）不在。运行时会补一份最小元数据后重试导入；仍失败时提示会点名真正缺的包并给「自动安装」入口。
  • No module named 'pickletools'：看着像包名，其实是 Python 标准库，pip 装不出来。界面会说明「这是安装包缺少该模块，请更新版本」，不会让你反复点自动安装。

还有一类嵌套报错 Could not import module 'CLIPTextModel'，来自 transformers 的懒加载，真实原因被包了两层。现在的提示会把原始错误链一起列出来；看到这条别急着重装 diffusers，先读「原始错误」那一行。

第 4 步：音频场景检查 ffmpeg

语音识别的音频转码、解码需要 ffmpeg，安装包不随附（体积较大）。「本地模型」页有常驻的「下载 ffmpeg」按钮，缺它时显示、装好后自动收起；下载到应用 resources/bin，免安装、不需要管理员权限、不改系统环境变量。缺 ffmpeg 的报错不会再被回退链路伪装成「未安装语音识别库」。

第 5 步：还不行，就导出诊断包

「帮助 → 导出诊断包」会把主日志、错误日志、审计日志与环境摘要打包（逐行脱敏、单份最多 5000 行）。把它和界面显示的原始错误一起发给支持邮箱，比截图一句英文报错有用得多。

事实边界（写文案和答问时都要带上）

本地模型、依赖包与 ffmpeg 都是按需下载、不随安装包分发的组件，体积从几十 MB 到数 GB 不等；离线/内网机器需事先在有网环境准备好再导入。国内下载优先走国内镜像，GitHub 资源优先走加速镜像，并对文件做 SHA-256 校验，不完整会当场判失败而不是装出半截包。本地模型能力属专业版；免费版仍可用表格、文件、代码等节点。

想从最简单的路径开始，先看「首次启动 3 分钟跑通」；不装本地模型也能完成的工作，看「批量处理 Excel」。
