API Key 怎么存才不会写进流程文件

把 Key 写在节点配置里，导出流程给同事的那一刻就泄露了。这件事应该在工具层面被挡住，而不是靠人记着删。

存储：别用明文，也别只靠"配置文件权限"

基本要求是主密码 + 加密存储：Key 用 AES-256 加密后落盘，密钥由主密码经 PBKDF2 派生，应用启动时要求解锁。这样即使别人拿到配置文件，也读不出 Key。

再进一步是密钥与数据分离：Key 存在凭据库，流程里只存引用；导出的流程文件里根本不含 Key，自然也就不存在"忘了删"。

导出：脱敏要递归，不能只删顶层

分享包、审计证据包、诊断包、配置备份四类导出最容易漏。要做到：

  • 递归遍历所有键名，命中 api_key / apikey / token / password / secret / access_key 等键名直接置空；
  • 值里疑似密钥的字符串（长串随机字符、sk- 前缀等）也要处理；
  • 导出前明确告诉你脱敏了什么，而不是静默替换；
  • 治理约定（预算、敏感级别、审计级别）只导出与默认值不同的项，接收方导入时逐项确认，不静默生效。

分享：只读链接比"发文件"更安全

给同事看一条流程，不一定要给文件。只读分享链接的做法是：本机起一个临时 HTTP 服务 + 一次性令牌，默认 10 分钟有效、页面只读、无导入入口、没有活链接就关端口、默认仅局域网可访问。页面里只给节点结构，不含提示词、SQL、密钥与输入默认值。

需要对方能改，再导出分享包；需要团队共用，用「团队模板目录」（仅局域网、服务端只读、提交需审核）。

审计：默认脱敏，包含原文要留痕

审计证据包默认不含提示词与输出原文；要带原文必须显式勾选，并且这个动作本身会被记录。操作审计日志同样不写密钥明文，只记"谁在什么时候改了哪个凭据"。

四个自查问题

  1. 导出一次流程，用文本编辑器搜 sk-、token，能搜到吗？
  2. 分享给同事的是文件还是只读链接？
  3. 审计包里能看到原始提示词吗？是谁打开的"包含原文"？
  4. 换人接手时，Key 是交接凭据还是散落在聊天记录里？

只要第 1 题答案是"能搜到"，其余都不用问了——先修导出，再谈其他。

边界

  • 本地加密防的是"旁人拿到文件"，不防"拿到整机 + 主密码"；
  • 导出未加密数据时应用会显式风险告警，这不是阻止，是提醒；
  • 云模型的 Key 由你自己配置并直接与服务商结算，工具不代收、不托管；一旦把 Key 填进第三方页面，任何本地措施都失效。
