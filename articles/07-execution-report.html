把执行记录整理成一份能交给老板看的报告

跑了几百次自动化，老板只问一句「这东西到底省了什么」。截图和日志都交不出去，需要的是一份有口径、能校验的说明。

先有记录，才有报告

执行记录里存的是：状态、触发来源（手动/定时/批量/API/表单…）、每一步的输入输出摘要、耗时与 Token。没有这些，任何"省了多少"都是拍脑袋。

在此基础上，四个视图各回答一个问题：

视图 回答什么
运行洞察 哪一步最慢、最贵？耗时/Token/成本 Top5 + 按拓扑层的甘特图，能看出并行层与瓶颈
用量看板 这段时间用了多少？按流程与模型排行、与预算对比（近 7 / 30 天）
费用预估 下次大概花多少？按历史给 P10–P90 区间；没有历史就如实说"没有依据"
健康周报 自动化还在跑吗？每周汇总运行次数、成功率、费用与待处理问题

交出去的三层材料

  1. 结果文件：结果页支持导出 TXT / Markdown / JSON / CSV / Word / Excel / PDF 七种格式，按接收方习惯选；
  2. 一页摘要：健康周报那段可以直接转发的 Markdown 卡片，适合贴到群里或写进周报；
  3. 审计证据包（摘要版，专业版）：不含提示词与输出原文，仍带 manifest.json 的逐文件 SHA-256 与整包指纹，可重算校验；报告页有人读结论、类别分布与打印样式。

需要完整证据（含提示词与输出）时再显式勾选「包含原文」——这会产生留痕，属于合规动作，不要默认打开。

三个必须说清的口径

  • 执行记录、运行洞察、用量看板与费用预估在免费版即可使用；审计证据包、操作审计日志与高级导出（Word/Excel/PDF）属专业版，Word/Excel/PDF 之外的基础导出免费；
  • 预算只覆盖 AI token 费用，不包含你自己的服务器、网盘、第三方 API；
  • MCP / A2A 等外部调用只记录次数，不折算金额，也不进入预算熔断——对外报数时不要把它们算成钱；
  • 摘要版 ≠ 完整证据包，它证明"这次跑过、结果可校验"，但不足以做法律取证。

一份可以直接抄的报告结构

一、做了什么：流程名 + 触发方式 + 周期
二、跑了多少：次数 / 成功率 / 平均耗时（近 30 天）
三、省了什么：人工单次耗时 × 次数（用你自己的估算，写清假设）
四、花了多少：AI token 费用（P10–P90 区间），外部调用次数单列
五、哪里还不好：失败最多的那一步 + 下一步打算
附件：结果导出文件 + 审计摘要包（可选）

第五节不要省。只报喜的报告没人信；把"最慢的一步"和"下一步改什么"写进去，反而更容易拿到继续投入的支持。

边界

  • 费用是估算，模型调价后旧记录不会自动重算；
  • 采样不足时不要下结论（比如只有 3 次运行就谈"平均节省"）；
  • 审计包的哈希校验只能证明文件未被改动，不证明业务结论正确。
