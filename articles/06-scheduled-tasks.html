定时任务总在半夜失败：错过执行、补跑与静默怎么设

自动化最烦的不是失败，是凌晨三点被通知吵醒，第二天还不知道该从哪一步补。

先把规则和"未来会发生什么"看清

定时任务的四类规则：间隔 / 每天 / 每周 / 每月。容易被忽略的是「未来 7 天触发预览」——上线前先看一眼接下来会在什么时候跑，比事后看日志强得多。跨月、跨周的场景尤其要预览，比如"每月 31 日"在 2 月会发生什么。

无人值守的四条防线

  1. 失败重试：单次失败按策略重试，不是一次就放弃；
  2. 连续失败自动停用：避免一条坏流程整夜反复失败、反复扣费；
  3. 单次超时：卡死的任务不会拖到下一个周期；
  4. 错过执行提醒：机器休眠、关机导致没跑，会明确告诉你跳过了哪一次（而不是静默丢失）。

还有一个常被忽略的点：交互节点在无人值守时会卡住。配置时会校验并给替换建议，或者允许「固定内容」的方式预置回答——否则半夜弹一个对话框，任务就停在那儿等天亮。

通知要能"停下"

  • 免打扰时段：夜间不弹；
  • 级别门槛：只推失败，不推成功；
  • 同类折叠：连续同类失败合并成一条；
  • 关注流程优先：只对重要的几条开高优先级。

通知渠道上，邮件与应用内通知中心免费可用；Webhook（企业微信 / 钉钉 / 飞书 / 自建）属专业版，飞书与钉钉能发卡片按钮，企微会降级成文本链接。

还需要一份"周报"

定时任务最怕的是悄悄停了没人发现。健康周报会每周主动汇总全部来源的运行情况（跑了多少次、成功率、费用、有没有待处理问题），周报自身失败只写日志、不打扰你。它证明的是"自动化还在跑"，而不是又给你加一个要看的面板。

边界（很重要）

  • 这是本机调度，不是云调度：电脑关机、休眠、退出应用，任务就不会跑；需要 7×24 的，得放在常开的机器或改用云端方案；
  • 文件夹监听与 API 触发表单默认关闭，需要显式启用并二次确认；
  • API 触发默认只监听 127.0.0.1，每个流程独立 Token（只存摘要），不要为了"方便"把它暴露到公网；
  • 定时任务走正式执行链路，会写执行记录并计入预算，和"不落库试跑"不是一回事。

一个可照做的顺序

先在编辑器里手动跑通 → 用样例数据试跑确认 → 建定时任务并看未来 7 天预览 → 配好通知级别与免打扰 → 第二天看执行记录与周报。

免费版的定时任务限 1 个，足够验证"这件事值不值得每天自动跑"。
