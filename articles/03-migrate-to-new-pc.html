换电脑不丢流程：拷贝数据目录（附必须带走的清单）

事实依据：数据目录 = 应用目录（config.py 的 DATA_DIR 固定为应用根目录）；知识库/经验库/执行记录在 smartxjflow.db；定时任务与 MCP/A2A 配置在同目录的 JSON；授权文件用机器码加密，跨机必然失效。

换机最省事的做法不是逐条导出流程，而是退出应用后把数据文件拷到新机的同一位置。比逐条导出更完整——知识库、经验库、执行记录、定时任务、MCP 配置全都一起走，不用重建。

一句话流程

  1. 旧机：完全退出应用 → 拷贝下面「必须带走」的文件与目录；
  2. 新机：解压不低于旧机的版本 → 放回应用目录的同名位置 → 首次启动自动升级数据库结构 → 重新登录账号。

一、必须带走的清单

路径都相对于应用目录（SmartXJFlow.exe 所在目录）。

文件 / 目录 里面是什么 备注
smartxjflow.db + smartxjflow.db-wal + smartxjflow.db-shm 流程、执行记录、知识库、经验库、AI 接口与加密凭据 三个文件必须一起拷：WAL 里可能还有未合并的最新写入，只拷 .db 会丢最近的改动
config.json 设置、主密码状态（salt / 验证哈希）、SMTP、路径与日志配置 必须与 db 一起走，否则加密凭据解不开，要重新填 API Key
schedules.json、schedule_state.json、schedule_missed_notice.json 定时任务规则与执行状态 一起拷，定时任务不用重建
mcp_servers.json、a2a_agents.json MCP Server 与 A2A 智能体配置 命令行参数里的本机路径需要检查
workflow_meta.json 流程列表附加元信息 小文件
ai_assistant_conversations.json、snippets.json 助手会话、代码片段 不需要可跳过
team_templates/ 团队模板目录 没用过就没有
batch_archive/、batch_checkpoints/ 批量结果归档、断点续跑检查点 体积随使用增长，只带需要的
folder_watch/、drafts/、output/ 监听状态、草稿、默认输出 输出目录若指向别处，按实际路径拷
vad/、notifications/ VAD 模型、通知历史 不用语音可跳过

二、不要带走的

文件 / 目录 原因
license.json、license_cookies.json 用本机机器码派生密钥加密，换机必然解不开，会被自动视为未登录——直接跳过，新机重新登录
resources/ 程序资源 + 本地模型权重（可能十几 GB），不要整体覆盖新机目录；模型按需重新下载
extensions/ 运行时依赖，按需下载；跨机拷贝容易出现半截包
update/ 升级暂存与回滚文件，可再生成
*.log、smartxjflow*.log 日志，不必占用迁移体积
程序本体（exe、_internal/ 等） 新机直接解压新版本更稳，也避免旧程序打不开新库

三、四个坑

  1. 漏拷 -wal：最容易踩。WAL 文件里还有未合并的写入，只拷 smartxjflow.db 会丢最近的改动；
  2. 停不干净：应用还在后台跑就拷，等于拷了个旧快照；
  3. 授权不会跟着走：这是设计如此（防止整目录拷贝复用账号），新机重新登录即可；
  4. 路径不会自动改：默认保存路径、流程里文件/文件夹节点的绝对路径、文件夹监听目录都要检查，否则会报"找不到文件"。

四、到了新机再做三件事

  1. 启动一次，让数据库自动迁移到当前版本；访问凭据时输入旧机的主密码；
  2. 在「设置 → 账户与授权」登录账号、登记新设备、清掉不再使用的旧设备；
  3. 跑「运行前体检」+ 一条最简单的流程，确认接口连通、依赖与本地模型按需下载。

五、只想交给同事一条流程？

那就别搬目录：用「文件 → 导出」导出单条流程（普通 JSON 或分享包，导出默认勾选脱敏），或用应用内「只读分享链接」——本机 HTTP + 一次性令牌、默认 10 分钟、页面只读无导入入口、无活链接即关端口、默认仅局域网，页面只给节点结构，不含提示词、SQL、密钥与输入默认值。小团队共用还能用「团队模板目录」（仅局域网、服务端只读、提交需审核）。

六、一条容易忽略的边界

云同步以分享包为载荷，按 workflow_id / updated_at / version 判冲突。它是流程分发，不是整机备份：知识库、执行记录、设置与授权不会跟着同步。别把"我开了云同步"当成换机备份。
